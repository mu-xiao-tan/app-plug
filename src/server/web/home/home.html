状态如何判断？

服务约每 20 秒向上游入口发送一次 HEAD 请求，单次最多 2 秒。收到任何 HTTP 响应（包括 401 或 403）即为「可达」，不代表公网能访问、访问已授权或应用功能正常。

查看完整指令 
在 App Plug 中添加用户指定的一个应用，不修改已有应用。

{{template "prompt-auth"}} 使用有权添加该域名的部署令牌或管理员令牌。

先确认目标域名和应用类型。域名填完整域名或单个短名；短名自动追加 .{{.BaseDomain}}，不含协议、端口或路径。向已确认的管理源发送 POST {{.APIPath}}/routes，按类型二选一，用实际数据替换示例值：

已有服务：{"domain":"域名","name":"显示名称","address":"127.0.0.1:8080"}
address 填私有或回环 IP 加端口，不填 URL；此类服务不由导航启停。

本机托管：{"domain":"域名","startFile":"/path/to/demo-app/run","args":[],"autoStart":false}
仅管理员可设置启动文件和参数。startFile 填导航主机上可信可执行文件的绝对路径；args 逐项传入，不经 Shell。按用户要求设置 autoStart；可选 port，省略或为 0 时自动识别监听端口。

两类配置不能混用；可另填 description。确认返回 201 才算添加成功。遇到 401、403、404 或 409，报告原因，不绕过权限、不覆盖路由。

只修改 App Plug 中用户指定的一个现有应用；不创建新应用。

{{template "prompt-auth"}} 使用有权管理该应用的令牌；修改本机托管配置需要管理员令牌。

确认原域名和要变更的字段。域名可用全名或短名；短名自动追加 .{{.BaseDomain}}。向已确认的管理源发 GET {{.APIPath}}/routes/<原域名>，不存在则报告，不新建。fileManaged 为 true 时，交由主机管理员修改配置文件。

向同一地址发 PUT，带 If-Match: * 并提交完整的可写配置。保留未修改的 name、description，以及已有服务的 address 或本机托管的 startFile、args、port、autoStart。不要把 owner、url、running、ready、upstream、fileManaged 或 launcher 回填。改域名时填 newDomain；如正文包含 domain，仍填与 URL 等价的原域名。

如需保留旧节点配置，使用原短别名作 URL 中的域名，只提交 node、port、name 和可选的 description；不自行迁移节点配置。

确认返回 200 才算更新成功。收到 401、403、404、409 或 412 时报告原因；不得去掉 If-Match、覆盖冲突域名或改动其他应用。

使用 App Plug 临时 API Key 添加管理员预先填写的一个应用。没有签发回执时，先请用户向管理员取得回执。

{{template "prompt-auth"}} 仅使用另行提供的临时 Key，不使用常规部署令牌或管理员令牌。

向用户确认签发回执中的 POST 地址；本实例的路径为 {{.APIPath}}/routes。请求体只发送 {"domain":"回执中的完整域名"}，按回执原样填写，不添加其他字段或替换域名。

返回 201 表示添加成功并消费该密钥，此后不能再使用；临时 Key 本身也不能查询或修改应用。收到 401、403、404 或 409 时报告原因，不覆盖、不改其他应用。请求超时或结果不明时，请管理员核对是否已添加，不盲目重试或用临时 Key 查询。
