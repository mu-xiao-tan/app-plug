# 应用插座 · App Plug

## 确定实例和入口

1. 确认实例的管理地址、实际接口路径、目标域名和凭据类型。应用公开 URL 不是管理地址，只将凭据发往用户确认的管理入口。
2. 已运行的服务若直接用原 URL，无需注册；要分配新域名时，登记私有或回环 `IP:端口`。本机托管使用导航主机上用户指定的可信可执行文件绝对路径，不要求预先登记启动项。管理员凭据不等于对任意程序的运行授权。
3. 应用操作优先使用 [CLI](operations.md#应用-cli)；使用 REST、MCP 或签发临时密钥时读[接口参考](api.md)；部署、配置、重载、排障或回滚时读[常用运维](operations.md)。

## 按目标操作

| 目标 | 操作 |
| --- | --- |
| 添加 | 用 `app add`、REST `POST` 或 MCP `create_route`。域名冲突时报告，不改用覆盖操作。 |
| 仅添加预填应用 | 用签发回执中的完整域名运行 `app claim` 或 [REST 兑换](api.md#临时-api-key)。临时密钥不能查询或改配置。 |
| 修改 | 优先 `app update`，只传要改的字段；直接调用 REST 时，先 GET，再合并可写字段，PUT 带 `If-Match: *`。改名填 `newDomain`，路径仍用旧域名。`fileManaged: true` 的应用交由主机管理员修改。 |
| 启停 | 只对指定的本机托管应用操作；停止保留域名、配置和自启设置。`running` 与 `ready` 分别表示进程运行和已发现可用监听。 |
| 删除 | 仅在明确要求删除指定域名时调用；CLI 需 `--yes`。删除托管路由同时停止进程。 |

**验收：**添加或修改后核对返回域名和配置，再打开返回的 `url` 验证实际内容；停应用后核对 `running`，删除后确认查不到路由。区分「已保存」「进程就绪」「公开入口或内容已验证」，不要用首页的「可达」代替验收。

凭据通过私有文件或环境变量注入，不写入命令参数、提示词、日志或提交。不跟随会携带令牌的重定向。遇 `401/403` 先核对凭据和入口策略；遇 `409/412` 先核对冲突或路由是否已移除，不扩大权限或盲目重试。
